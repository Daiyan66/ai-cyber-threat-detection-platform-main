1. EXECUTIVE SUMMARY & PROJECT PURPOSE
====================================================================================================
The AI Cyber Threat Detection Platform is a full-stack, enterprise-grade Security Operations Center 
(SOC) console and Automated Intrusion Detection and Prevention System (IDS/IPS). Modern enterprise 
networks generate millions of packet conversations every minute; legacy signature-based intrusion 
detection systems (like basic Snort rules) fail to identify zero-day attacks, stealthy reconnaissance, 
and low-and-slow volumetric anomalies. 

This platform bridges the gap between raw binary network packet inspection and actionable security 
orchestration by combining:
1. Low-level binary packet parsing and bidirectional flow reconstruction (CICFlowMeter standard).
2. Supervised machine learning multi-model classification trained on modern telemetry (CIC-IDS2017).
3. Explainable AI (XAI via SHAP) to mathematically justify why the AI flagged an anomaly.
4. Generative AI (Google Gemini 1.5 Flash) acting as an automated Tier-1 SOC analyst to translate 
   complex flow metrics into plain-English incident summaries and remediation playbooks.
5. Bi-directional WebSocket telemetry streaming for zero-latency alert push across analyst consoles.
6. Security Orchestration, Automation, and Response (SOAR) capabilities that enforce active host OS 
   firewall drop rules (Windows netsh) and generate multi-platform defense syntax (Linux iptables, 
   Suricata, Snort).
7. One-click publication-grade PDF Forensic Incident Report generation for compliance and audits.

THE 22 CORE CICFLOWMETER STATISTICAL FLOW FEATURES:
----------------------------------------------------------------------------------------------------
 1. flow_duration      : Total conversation duration in milliseconds
 2. tot_fwd_pkts       : Total packets transferred from client to server (forward)
 3. tot_bwd_pkts       : Total packets transferred from server to client (backward)
 4. totlen_fwd_pkts    : Total payload bytes sent in forward direction
 5. totlen_bwd_pkts    : Total payload bytes sent in backward direction
 6. fwd_pkt_len_mean   : Mean length of forward packets (bytes)
 7. bwd_pkt_len_mean   : Mean length of backward packets (bytes)
 8. flow_byts_s        : Flow transmission velocity in bytes per second
 9. flow_pkts_s        : Flow packet rate in packets per second
10. flow_iat_mean      : Mean inter-arrival time between consecutive packets (ms)
11. flow_iat_std       : Standard deviation of packet inter-arrival times
12. fwd_iat_mean       : Mean inter-arrival time of forward packets
13. bwd_iat_mean       : Mean inter-arrival time of backward packets
14. syn_flag_cnt       : Presence/count of TCP SYN (Synchronize) control flags
15. rst_flag_cnt       : Presence/count of TCP RST (Reset connection) control flags
16. psh_flag_cnt       : Presence/count of TCP PSH (Push buffer) control flags
17. ack_flag_cnt       : Presence/count of TCP ACK (Acknowledge) control flags
18. urg_flag_cnt       : Presence/count of TCP URG (Urgent pointer) control flags
19. fwd_header_len     : Total bytes consumed by forward packet headers
20. bwd_header_len     : Total bytes consumed by backward packet headers
21. down_up_ratio      : Download-to-upload asymmetry ratio (tot_bwd_pkts / tot_fwd_pkts)
22. pkt_len_variance   : Variance of overall packet sizes within conversation
23. subflow_fwd_pkts   : Average forward packets in sub-flow conversations

7. EXPLAINABLE AI (XAI) & SHAP FEATURE ATTRIBUTION
====================================================================================================
In real-world cybersecurity, black-box AI is dangerous: an alert that cannot be explained leads to 
analyst fatigue and mistrust. 

The platform integrates SHAP (SHapley Additive exPlanations) directly into the investigation drawer:
1. Engine: shap.TreeExplainer (backend/app/xai_service.py).
2. Theory: Based on cooperative game theory (Lloyd Shapley, Nobel Memorial Prize). It treats each 
   of the 22 flow features as players in a game and computes their marginal contribution to the 
   model's prediction difference from the baseline expected value.
3. Visualization: When an analyst opens a threat drawer and clicks "Calculate SHAP", the backend 
   computes local Shapley values:
   - Red bars (Positive SHAP): Features pushing the prediction towards this attack class (e.g. 
     high SYN count, zero backward bytes, short duration).
   - Green bars (Negative SHAP): Features that opposed this classification.
4. Performance: Uses TreeSHAP, computing exact Shapley values in O(T * L * D^2) time instead of 
   exponential sampling time.

9. NETWORK PACKET INGESTION & ZERO-DEPENDENCY PCAP ENGINE
====================================================================================================
A flagship feature for examiner demonstrations is the Web UI Drag-and-Drop PCAP Ingestion engine:
- File Location: src/pcap_analyzer.py
- API Endpoint : POST /pcap/upload

----------------------------------------------------------------------------------------------------
HOW THE ZERO-DEPENDENCY BINARY PACKET PARSER OPERATES:
----------------------------------------------------------------------------------------------------
Standard tools like Wireshark or Scapy require heavy C libraries (libpcap/Npcap). Our engine is 
written in 100% pure Python standard library using 'struct.unpack':

1. PCAP Global Header (24 Bytes):
   - Unpacks 4-byte Magic Number (0xa1b2c3d4 or 0xd4c3b2a1).
   - Validates major version (2), minor version (4), snapshot length (65535), and LinkType (1 = Ethernet).
2. Packet Header (16 Bytes per packet):
   - Unpacks timestamp seconds (ts_sec), microseconds (ts_usec), and captured packet length (incl_len).
3. Ethernet Frame Header (14 Bytes):
   - Strips 6-byte Destination MAC, 6-byte Source MAC.
   - Validates EtherType (0x0800 = IPv4). Skips non-IPv4 frames.
4. IPv4 Header (Minimum 20 Bytes):
   - Parses Version and Header Length (IHL).
   - Extracts Protocol (Byte 9: 6 for TCP, 17 for UDP).
   - Unpacks Source IP and Destination IP via socket.inet_ntoa().
5. TCP Header (Minimum 20 Bytes):
   - Unpacks Source Port and Destination Port.
   - Extracts TCP Control Flags (Byte 13): Bitwise AND for SYN (0x02), RST (0x04), ACK (0x10).
6. Flow Reconstruction:
   - Groups packets by their 5-tuple: (Source IP, Destination IP, Destination Port, Protocol).
   - Tracks packet count, byte volume, duration, and control flag counters.
7. Feature Vector Synthesis:
   - Transforms the conversational metrics into the 22-dimensional feature vector.
   - Evaluates Random Forest classifier, tags with MITRE ATT&CK technique, writes to database, and 
     broadcasts alert via WebSocket.

13. ACTIVE FIREWALL CONTAINMENT & SOAR INTEGRATION
====================================================================================================
The platform functions not just as a passive monitor (IDS), but as an active defense system (IPS/SOAR):

1. Host OS Firewall Containment:
   - When an analyst clicks "Block Attacker IP" with OS enforcement enabled, the backend executes:
     subprocess.run(["netsh", "advfirewall", "firewall", "add", "rule", 
                     f"name=SOC_BLOCK_{ip}", "dir=in", "action=block", f"remoteip={ip}"])
   - Drops all incoming packets from that source IP address at the kernel network stack level.
   - Updates the database record to mark 'is_blocked = True' and 'status = resolved'.

2. Multi-Platform Rule Syntax Generator (GET /threats/{id}/rules):
   - Windows Netsh  : netsh advfirewall firewall add rule name="SOC_BLOCK_{IP}" dir=in action=block remoteip={IP}
   - Linux IPTables : iptables -A INPUT -s {IP} -j DROP
   - Suricata Rule  : drop ip {IP} any -> any any (msg:"SOC Auto-Containment IP {IP}"; sid:100{ID}; rev:1;)
   - Snort Rule     : drop ip {IP} any -> any any (msg:"SOC Auto-Containment IP {IP}"; sid:200{ID}; rev:1;)

17. EVALUATOR & VIVA EXAMINATION QUESTIONS WITH ANSWERS
====================================================================================================
----------------------------------------------------------------------------------------------------
COMPUTER NETWORKS (CN) QUESTIONS:
----------------------------------------------------------------------------------------------------
Q1: What is a Network Flow, and what constitutes the 5-Tuple?
A1: A network flow is a sequence of packets transferred between two endpoints within a specific time 
    window sharing the identical 5-tuple:
    (1) Source IP, (2) Destination IP, (3) Source Port, (4) Destination Port, (5) Protocol (TCP/UDP).
    Rather than inspecting individual isolated packets, flow-based analysis tracks bidirectional 
    conversations and computes statistical features (packet rates, byte rates, inter-arrival times), 
    enabling detection even when payloads are encrypted with TLS/HTTPS.

Q2: How does a TCP SYN Flood work, and how does your model detect it?
A2: In normal TCP three-way handshake: Client sends SYN -> Server responds SYN-ACK -> Client sends ACK.
    In a SYN Flood (MITRE T1498), the attacker sends thousands of SYN packets from spoofed IPs without 
    returning the final ACK. The server's half-open connection backlog queue becomes exhausted.
    Our model detects this via three primary features:
    (a) syn_flag_cnt = 1, (b) tot_bwd_pkts ~ 0 (down_up_ratio = 0.0), (c) extremely short flow_iat_mean.

Q3: How does your PCAP parser read packets without third-party tools like Scapy?
A3: Using Python's built-in 'struct.unpack' module. We read the 24-byte PCAP global header to verify 
    the magic number (0xa1b2c3d4). Then, for each packet, we read the 16-byte packet header to determine 
    length, skip the 14-byte Ethernet header, unpack the 20-byte IPv4 header to extract IPs and protocol, 
    and unpack the 20-byte TCP header to extract ports and flags (Byte 13).

----------------------------------------------------------------------------------------------------
MACHINE LEARNING & CYBERSECURITY QUESTIONS:
----------------------------------------------------------------------------------------------------
Q4: Why did you choose Random Forest over Deep Learning (MLP)?
A4: As shown in our academic benchmark (ml/metrics.json):
    - Random Forest achieved 99.50% accuracy compared to 99.00% for MLP.
    - Random Forest trained in 0.63 seconds compared to 9.95 seconds for MLP (15x faster).
    - Random Forest supports exact polynomial-time SHAP TreeExplainer, giving our analysts true 
      mathematical explainability, whereas neural networks are black-boxes requiring slow approximations.

Q5: What is Explainable AI (XAI) and why is SHAP needed in a SOC?
A5: When an AI flags an alert, a SOC analyst cannot take high-impact containment actions (like blocking 
    an IP or isolating a server) without understanding the reasoning. SHAP (SHapley Additive 
    exPlanations) calculates the game-theoretic contribution of each network feature. For example, it 
    shows the analyst: "This flow was classified as DDoS because packet length variance was 0 and SYN 
    count was 1, contributing +0.42 towards the DDoS prediction."

Q6: What is MITRE ATT&CK and how is it integrated?
A6: MITRE ATT&CK is the globally recognized cybersecurity knowledge base of adversary tactics and 
    techniques. We map every detected attack type to its official technique ID:
    - DDoS        -> T1498 (Network Denial of Service)
    - PortScan    -> T1046 (Network Service Discovery)
    - Brute Force -> T1110 (Brute Force Credentials)
    - Web Attack  -> T1190 (Exploit Public-Facing Application)
    - Botnet      -> T1071 (Application Layer Protocol - C2)

Q7: What is SOAR and how does your platform implement it?
A7: SOAR stands for Security Orchestration, Automation, and Response. Instead of requiring the analyst 
    to manually log into routers or firewalls, our platform provides active containment: clicking 
    "Block Attacker IP" invokes the Windows Host Firewall ('netsh advfirewall') or outputs ready-to-run 
    Linux IPTables and Suricata IDS rules.
